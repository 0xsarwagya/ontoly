# Migration Analysis Examples

Each example is graph-first and MCP-first.

| Repository | Questions | Expected workflow | Capabilities invoked | Expected evidence | Expected answer |
| --- | --- | --- | --- | --- | --- |
| NestJS | Trace a request through a NestJS controller, guard, and service. | Follow shared workflow, run `EvidencePack` first, then `ExplainArchitecture` then `ImpactAnalysis` then `FindConfigurationUsage` then `FindDependencies`, inspect files only if graph evidence is missing. | `EvidencePack`, `ExplainArchitecture`, `ImpactAnalysis`, `FindConfigurationUsage`, `FindDependencies` | controller, route, service, dependency-injection edges; graph hash; confidence. | A migration plan with graph-defined scope, impact, rollout order, risks, evidence, and confidence. |
| Express | Explain the package entrypoint and public API surface. | Follow shared workflow, run `EvidencePack` first, then `ExplainArchitecture` then `ImpactAnalysis` then `FindConfigurationUsage` then `FindDependencies`, inspect files only if graph evidence is missing. | `EvidencePack`, `ExplainArchitecture`, `ImpactAnalysis`, `FindConfigurationUsage`, `FindDependencies` | package, exports, functions, interfaces; graph hash; confidence. | A migration plan with graph-defined scope, impact, rollout order, risks, evidence, and confidence. |
| Hono | Find middleware APIs and their consumers before a refactor. | Follow shared workflow, run `EvidencePack` first, then `ExplainArchitecture` then `ImpactAnalysis` then `FindConfigurationUsage` then `FindDependencies`, inspect files only if graph evidence is missing. | `EvidencePack`, `ExplainArchitecture`, `ImpactAnalysis`, `FindConfigurationUsage`, `FindDependencies` | functions, interfaces, dependents, configuration; graph hash; confidence. | A migration plan with graph-defined scope, impact, rollout order, risks, evidence, and confidence. |
| Turborepo | Summarize workspace packages and package dependencies. | Follow shared workflow, run `EvidencePack` first, then `ExplainArchitecture` then `ImpactAnalysis` then `FindConfigurationUsage` then `FindDependencies`, inspect files only if graph evidence is missing. | `EvidencePack`, `ExplainArchitecture`, `ImpactAnalysis`, `FindConfigurationUsage`, `FindDependencies` | workspace, packages, framework nodes, dependency edges; graph hash; confidence. | A migration plan with graph-defined scope, impact, rollout order, risks, evidence, and confidence. |
| Next.js | Identify app routes and request ownership. | Follow shared workflow, run `EvidencePack` first, then `ExplainArchitecture` then `ImpactAnalysis` then `FindConfigurationUsage` then `FindDependencies`, inspect files only if graph evidence is missing. | `EvidencePack`, `ExplainArchitecture`, `ImpactAnalysis`, `FindConfigurationUsage`, `FindDependencies` | routes, route handlers, modules, services; graph hash; confidence. | A migration plan with graph-defined scope, impact, rollout order, risks, evidence, and confidence. |
